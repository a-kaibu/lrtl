# シーケンスフォルダーのリネーム

```powershell
# 変更予定を表示
lrtl rename-sequence C:\photos\Sequence --name "Day 01_日本語"
# フォルダー名を変更
lrtl rename-sequence C:\photos\Sequence --name "Day 01_日本語" --write
```

同じ親フォルダー内で、シーケンスのフォルダー名を変更します。画像名、XMP、隠しファイル、`.lrt`設定・キャッシュ、バックアップ、サブフォルダーを含む全内容をそのまま移します。XMPの解析や書換は行わないため、不正なXMLや読めない画像が含まれていてもフォルダー改名のために内容を変換しません。ファイル内容・更新日時・権限を保持します。

## 入力と衝突

- 既定はプレビュー。`--write`で実行します。
- 新しい名前は1つのフォルダー名です。パス・親への参照・絶対パス・Windows予約名・制御文字・末尾ドット等を拒否します。可搬性のためUTF-8で1〜255バイトに制限します。
- ファイルシステムのルートと、シンボリックリンク自体を改名元にする指定を拒否します。親のリンクは解決し、実際の改名元／改名先をプレビューに表示します。
- 移動先にファイルやフォルダーがある場合はエラーです。大小文字を区別しない衝突も事前に検査します。
- 通常変更はOSの上書き禁止ディレクトリ改名を1回実行します。検査後に同じ移動先が出現しても、既存の空フォルダーを上書きしません。
- 実際の名前と同じ指定は変更なしで成功します。Windowsで入力パスの大小文字が異なる場合も、ディスク上の名前で判定します。

## 大小文字だけの変更

`Sequence`→`sequence`のような変更では、親の`.lrtl-rename-*`フォルダー内へ一時退避してから公開します。通常の2回目の移動失敗は元へ戻します。復元にも失敗した場合は、データを退避場所に保持してそのパスをエラーへ表示します。非空の退避フォルダーを削除する処理はありません。

2段階の間でプロセスが強制終了した場合の自動復旧や永続ジャーナルは未実装です。その場合は親の`.lrtl-rename-*/sequence`が退避場所です。他のアプリによる同時のフォルダー操作全体を排他制御するものではありません。

## 対応環境と参照パス

実行はWindowsとLinuxに対応します。Windowsは`MoveFileEx`を置換フラグなしで使い、長いパスにも対応します。Linuxは`renameat2(RENAME_NOREPLACE)`を使います。必要なOS／ファイルシステム機能が利用できなければエラーを返し、上書きを許す方法へフォールバックしません。他のOSはプレビューのみで、実行は未対応エラーになります。

保存した選択JSONなどに含まれる絶対パスは書き換えません。改名後は新しいフォルダーで`select`を再実行してください。外部アプリの最近使ったフォルダー、絶対リンクや設定全体の移行も対象外です。個々の画像の改名や別の親への移動は、このコマンドでは扱いません。

## LRTとの対応範囲

インストール済みLRT 7.5.5の`cOM7`のフォルダー改名処理を調べ、同じ親に新しい名前を作り、置換オプションなしのJava `Files.move`を呼ぶ構造を確認しました。Go CLIではこのフォルダー単位の機能を実装しています。CLIのプレビュー・名前制限・大小文字変更時の退避と復元は独自の実装です。

本体GUIでの入力、確認ダイアログ、ツリー更新、ロックされたファイルやネットワークドライブの全動作との比較は未実施です。製品の内部実装やリソースは含みません。
