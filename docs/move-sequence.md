# 選択した画像を別フォルダーへ移動

`move-sequence`はWindowsとLinuxで、選択した画像と付随ファイルを新規フォルダーへ移動します。既定はプレビューです。

```powershell
lrtl move-sequence C:\photos\sequence --output D:\photos\selected --ratings 4,5
lrtl move-sequence C:\photos\sequence --output D:\photos\selected --ratings 4,5 --write
```

`--selection FILTER.json`、`--filename-contains TEXT`、`--ratings LIST`の積集合を使い、`--invert`で反転できます。移動先は元フォルダーの外にある未作成のフォルダーが必要です。異なるファイルシステムにも対応します。`--merge`を付けると既存フォルダーへ追記でき、同内容のXMP／キャッシュだけを再利用します。同名画像の上書きはしません。[追記・衝突・復元の詳細](remove-sequence.md)を参照してください。

同じドライブ内でも検証用コピーを作るため、移動先には対象ファイル一式の空き容量が必要です。

## 対象と保持するファイル

- 選択した画像。
- 既定では同名JPEGも追加します。例えば`a.nef`を選ぶと、存在する`a.jpg`も対象になります。選択数より移動する画像数が増えることがあります。
- 各対象画像の両方の外部XMP候補（`a.xmp`と`a.nef.xmp`など）。現在は採用されていない候補も、そのまま運びます。
- 既定では画像別の`.lrt/previews/<stem>.lrtpreview`、`.lrt/visual/<stem>.lrtpreview`、`.lrt/proxy/<stem>.proxy`。

`--include-lrt-companions=false`で追加JPEGとキャッシュを省けます。これは、付随ファイル追加が既定オフの`copy-sequence`とは異なります。未選択画像にも必要なXMP・キャッシュは移動先へコピーし、元にも残します。連番全体の設定、履歴、バックアップ、無関係なファイルと空ディレクトリは元に残します。

ファイル内容・更新日時・Goで扱えるパーミッションを保持します。ACL、所有者、拡張属性の再現は保証しません。XMPの書き換えやRAWの再圧縮は行いません。絶対パスを保存した選択JSONは移動後に再生成してください。

## 途中失敗と復元

1. 移動先と同じファイルシステムの一時フォルダーへコピーし、コピー前後の元ファイルとコピーのSHA-256を比較します。
2. 元フォルダーに`.lrtl-move-*`を作り、移動計画を`move-journal.json`へ保存します。共有分以外の原本を、その中へ一時退避します。
3. 原本の同一性と内容を再確認し、コピー済みフォルダーを移動先として公開します。既存の移動先は置き換えません。`--merge`で既存先へ追記するときは、各ファイルを個別に公開します。
4. 公開したコピーと原本の内容を再確認してから、退避した原本を削除します。

公開前の通常の失敗では原本を戻します。復元にも失敗した場合は、原本と検証済みコピーを保持し、両方の場所をエラーに表示します。公開後の原本削除に失敗した場合は、完成した移動先と残っている原本を保持してエラーにします。読み取り専用属性を解除して原本を削除することはしません。Windowsで必要な削除操作がファイルシステムに対応していない場合も、この保持処理になります。

強制終了・電源断からの自動復旧コマンドは未実装です。途中で止まった場合は、ジャーナルの`Original`（元の場所）、`Held`（退避先）、`SHA256`、`KeepOriginal`と、実際の移動先の内容を確認して手動復元が必要です。`published.json`は公開後に書く補助記録で、これがないことだけでは未公開と判断できません。処理中に他のアプリで元・移動先・一時フォルダーを変更しないでください。電源断への耐久性や同時書き込みの完全な隔離を保証するものではありません。

## テストと本体との比較範囲

Goのテストで、共有XMP／キャッシュの保持、非採用XMP、内容・時刻・属性、読み取り専用ハードリンク、計画後のファイル・元ディレクトリ変更、コピー破損、退避・公開・復元・後片付けの失敗、途中の出力先衝突、プレビュー、CLI評価選択、再実行拒否、移動前後のAVI画素を検査します。失敗箇所とファイル内容を変えるfuzz testも含みます。Linuxでは`/tmp`から`/dev/shm`への実移動も検査します。

```powershell
go test ./internal/lrtl -run '^TestMoveSequence' -count=2
go test -race ./internal/lrtl -run 'Test(MoveSequence|CopySequence|SequenceCompanions)' -count=2
go test ./internal/lrtl -run '^$' -fuzz '^FuzzMoveSequenceRollback$' -fuzztime=30s
```

2026-10-24のWindows実行では、関連raceテストと30秒のfuzz（2,116ケース）が通過しました。Ubuntu 24.04でも移動テストを2回実行し、別ファイルシステムのテストがスキップされず通過しています。ビルドしたCLIで日本語パスの画像2枚・XMP2個・キャッシュ3個を移動し、移動前後のAVIをFFmpegでRGBへ復号した12,288サンプルが一致しました。これらは作成したテスト素材での確認です。

CGOを無効にした全体回帰テスト`go test -p 1 ./...`も通過しました（Go 1.26.9、`internal/lrtl`は152.823秒）。`go vet ./...`とCLIビルドも通過しています。

同名JPEGと3種類のキャッシュのパス計算は、実LRT 7.5.5の24条件と比較済みの[付随ファイル判定](sequence-companions.md)を共有しています。本体の呼び出し関係から確認した移動対象を参考に、移動・検証・復元は独自実装しています。`_REMOVED`への除去には[remove-sequence](remove-sequence.md)を使えます。本体の移動全体、上書きダイアログ、完全削除と同等の動作を示すものではありません。
